把本体服务变成你自己的：三条扩展路径
改动量从小到大 · 全部零改核心代码（reasoner/ 不动）
路径 A · 换同构本体改动最小 · 复用全部领域查询
1 换 .owl（类/属性名不同，公理结构保留）
2 引擎传命名空间（坑：默认 NS 是示例本体的）
eng = OntologyEngine("your.owl",
ns="http://example.org/your#")
3 语义配置改类角色映射
DEFAULT_CONFIG.update(
agent_class="Worker", task_class="Job",
complex_task_class="Pipeline",
has_capability="owns_skill",
requires_capability="needs_skill")
4 领域查询（匹配/编排/分配）原样复用
实测：agents()=worker_a · tasks()=job_x · 复合任务 pipe_p 识别 ✓
路径 B · 新建领域异构业务 · 拷贝模板七步
1 建目录 domains/<name>/，拷贝 agent_task 作模板
2 替换本体 .owl（Protege 建模，中文名放 rdfs:label）
3 改 config.json 类角色映射
4 改 derivation.json 推导链文案
5 重写 adapter.py 查询方法，暴露 NAME/DESCRIPTION/ONTO_FILE
6 （可选）mcp.py 注册领域工具
7 验证：list_domains() → load_domain() → mcp --domain 切换
引擎 / API / MCP / CLI 全部零改动
路径 C · 加规则 / 查询在现有领域上增量
能 OWL 表达（属性链/传递/子类）→ 加进 .owl 公理，owlrl 自动推理
需遍历/业务判断 → 适配器加方法
推导链 → derivation.json 加对应 key（否则"为什么"缺文案）
暴露出口 → API 加端点 或 mcp.py 加 @server.tool
新查询类型 = 适配器方法 + derivations key + 出口注册（三处联动）
路径 A：改配置不改代码 路径 B：新领域包，核心零改动 路径 C：规则/查询增量三处联动
共同前提：核心层（reasoner/）零领域词汇——所以无论怎么扩展，引擎、API、MCP、CLI 都不用改；你维护的只是「本体 + 配置 + 适配器」。
