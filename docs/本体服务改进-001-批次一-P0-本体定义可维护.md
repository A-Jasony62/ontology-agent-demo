## 1. 目标

- 本体从"单一 .owl"变为"核心 .owl + extensions/ 增量块"，新增/回滚不触碰核心定义；
- classify/assign 的运行时变更可选持久化，重启不丢；
- 消除 assign 状态"仅内存 dict、任何进程 reload 都无法恢复"的盲区。

## 3. 关键设计

### D-P1-1 engine 多文件加载（REQ-06）

```
OntologyEngine.__init__(onto_path, extensions_dir=None, ns=None)
  raw = Graph(); g = Graph()
  raw.parse(onto_path); g.parse(onto_path)           # 核心定义（保持原样）
  if extensions_dir:                                  # 新增
      for f in sorted(extensions_dir.glob("*.ttl") + extensions_dir.glob("*.owl")):
          raw.parse(f); g.parse(f)                    # 按文件名排序加载
  owlrl expand(g)                                     # 统一推理
```

- `_resolve_ns` 改造：**优先用 IRI 频率分支**（现有 `engine.py:75-95` 已具备），不再依赖 `ET.parse(onto_path)` 文件头（多文件下文件头无意义）；
- `raw` 快照 = 核心 + 全部扩展的原始断言（保证 `materialized()` 物化 diff 正确）；
- **重复个体策略**：加载时若扩展与核心存在同名个体（IRI 相同但断言冲突），不做静默覆盖——由校验阶段（批次三 REQ-08）统一检测；加载本身允许追加断言（RDF 图语义天然合并）。

### D-P1-2 reload 原语（原子切换，批次二 REQ-01 的地基）

```
engine.reload() -> dict   # 新实例：parse（核心+extensions）→ 推理；成功才替换 self 状态
   失败（解析/推理异常）→ 抛错，旧状态原样保留
```

实现：`OntologyEngine.reload()` 内部构造临时 `Graph` 完成全部加载与推理后，整体替换 `self.raw / self.g / self.NS`（图替换为原子操作，无中间态）。

### D-P1-3 assign 改图断言（BLOCK-1）

`adapter.assign()` 从"写 dict"改为"**写图 + 同步缓存**"：

```python
def assign(self, task_iri, agent_iri, ...):
    self.engine.add_triple(local(task), "assigned_to", local(agent))  # 图断言（新）
    self.assignments[local(task)] = local(agent)                       # 缓存保持（兼容现有读取）
```

- `consistency()` / `graph_export()` 读取源**改为图**（`subject_objects("assigned_to")`），dict 仅作兼容缓存；
- 语义：assign 成为**可持久化、可 reload 恢复**的本体状态；
- R4 冲突检测逻辑不变。

### D-P1-4 persist 增量写回（REQ-05）

```
classify(name, capabilities, constraints, risk_level, persist=False) -> dict
assign(..., persist=False) -> dict
```

- `persist=true` 时，将本次新增的**断言级增量**用 rdflib 构造 RDF 写入扩展文件：

```
extensions/YYYYMMDD-HHMMSS-<操作>-<名称>.ttl
  # 例如 20261021-153005-classify-t_compliance_test.ttl
  <...#t_compliance_test> a <...#SimpleTask> ;
      <...#requires_capability> <...#Coding> ;
      <...#requires_constraint> <...#ComplianceRequirement> ;
      <...#has_risk_level> 5 .
```

- **序列化源**：直接用本次操作的断言参数构造（**不依赖图 diff**，天然排除推理物化与历史噪音）；
- **原子写盘**：临时文件 + `os.replace()`；写盘失败不影响内存状态（已生效的内存变更回滚为"未持久化"，返回错误+变更仍可用）；
- 文件名含时间戳与操作名，天然支持排序（批次二 reload 按文件名加载即时间序）；
- 返回：`{"persisted": true, "path": "...", "triples": N}`。

### D-P1-5 变更计数（REQ-03 的 dirty 基础）

adapter 增加：`self.change_count`、`self.changelog`（内存，操作/时间/操作者/详情）——
classify/assign 每次执行自增并记录；`persist=true` 成功后 `change_count` 归零、日志标记 committed。
