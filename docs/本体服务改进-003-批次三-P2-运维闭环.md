## 3. 关键设计

### D-P3-1 ontologyctl（REQ-04）

```
scripts/ontologyctl.py status                 # 聚合 health + 两端一致性 + 进程监听状态
                       reload                 # POST /api/ontology/reload + kill -HUP MCP
                       commit --message       # persist 落盘校验 + git add/commit/tag
                       diff                   # changelog 未提交变更预览
                       rollback [tag]         # git checkout 本体文件 → reload
                       log                    # git log --oneline 本体相关 + changelog
```

- **纯 HTTP 客户端**（requests），不做进程内注入；MCP 一致性通过探测 `:9000` 状态（新增只读 status 工具或 lsof 探测）；
- 输出 JSON（`--json`）或结构化文本。

### D-P3-2 git 权威源与备份（REQ-07）

- 部署约定：**运行目录 = git 仓库**（当前 `/Users/yangyue/projects/ontology-agent-demo` 已是）；
- `commit` 自动：`git add` 变更（核心 .owl + extensions/ + config/derivation 等）→ commit → tag `v0.1.x-本体-YYYYMMDD-HHMMSS`；
- `scripts/backup.sh`：发布前备份 `domains/*/agent_task_ontology.owl` + `extensions/` 到 `backups/`（时间戳目录）；
- 若宿主应用（WorkBuddy sandbox）从临时目录运行：约定 commit 操作指向**权威源路径**（`ONTOLOGY_GIT_ROOT` 环境变量），同步后再 reload。

### D-P3-3 构建自检强化（REQ-08）

`build_ontology.py --clean` 流程中新增 4 项检查（在现有 `self_check` 基础上）：

| 检查 | 判据 |
|---|---|
| 短名唯一性 | 任务/智能体/能力个体短名无重复 |
| 引用完整性 | `requires_capability`→存在的能力类；`assigned_to`→存在的智能体；`composed_of`→存在的任务 |
| 依赖无环 | `depends_on` 拓扑排序通过（复用 `engine.topological_sort`），失败定位环路径 |
| 标签完整性 | 个体有 `rdfs:label`（中文名） |

**失败即不产出 .owl，退出码非 0，输出逐项报告**。

### D-P3-4 CRUD（REQ-09）

```
DELETE /api/ontology/individual/{name}?persist=false&cascade=false
   默认：删除个体 A-box 断言（类型/属性/数据）→ reparse → _apply_r2 → 清理 r2_asserted 中相关项
   cascade=true：连带清理依赖该个体的推理结论边
POST /api/ontology/revoke  {task, agent, persist}
   移除 assigned_to 图边（批次一已入图）→ 更新缓存
POST /api/ontology/import  {individuals: [classify 同构字段...], persist}
   事务：先全部校验（名称冲突/引用完整）→ 全部通过才应用 → 一次 reparse → 一次落盘
```

- 所有操作写 changelog（时间/操作/操作者/详情），`persist=true` 时写增量文件；
- 删除依赖保护：目标个体被 `composed_of`/`depends_on`/`assigned_to` 引用时拒绝（除非 cascade）。
